# Capabilities - What Can This Tool Do?

This document describes what's actually implemented and reachable through the app today, as opposed to what earlier drafts of this document described. If you're comparing against an older copy, everything under "Neural Network," "Machine Learning Predictions" (in the synthetic-model sense), "20+ materials," and "10+ machines" no longer applies — see [What's Not (Yet) Wired In](#whats-not-yet-wired-in) and [What Changed](#what-changed) at the bottom.

---

## Core Physics Calculations

### ✅ Pressure Drop Analysis
- Base pressure drop (Darcy–Weisbach equation)
- Friction factor (Swamee–Jain correlation)
- Pressure loss from fittings (~15% additional)
- Total pressure with fittings

### ✅ Flow Analysis
- Shear rate (γ̇, s⁻¹)
- Apparent viscosity, accounting for shear-thinning (power-law model)
- Reynolds number and flow regime: **laminar** (Re < 2300), **transitional** (2300–4000), **turbulent** (Re > 4000)
- Flow velocity

### ✅ Laminar Flow Margin
Beyond just labelling the regime, the tool reports how much room is left before the line turns turbulent: the flow rate at which it would cross over, the flow headroom as a ratio of the current rate, and the narrowest pipe diameter that would keep the current flow rate laminar. Avoiding turbulence in the feed line is the point of the tool, so this is a headline result, not a footnote.

### ✅ Thermal / Viscosity Effects
- **Arrhenius equation** for temperature-dependent viscosity, using each material's activation energy
- **Shear heating** — temperature rise generated by friction as material moves through the pipe

---

## Line Thermal Modelling (optional)

Supply an **ambient temperature** and, optionally, **time since the last shot**, and the tool models the material drifting toward ambient in the hose before it reaches the mix head — rather than assuming the tank set point holds the whole way through. This matters most for single-shot or intermittent work where material can sit in the line between shots. Leaving this blank keeps the calculation exactly as if the feature didn't exist.

---

## Blowing Agent Volatility (when the material names one)

Checks whether the blowing agent stays dissolved at the calculated line temperature and pressure, reporting one of: stays in solution, close to boiling (marginal), or flash-off risk. Where no sourced vapour-pressure data exists for an agent, the result says so explicitly rather than reporting a false pass.

---

## Cure & Exotherm Prediction (catalogued materials with reaction data, optional)

Supply a **part thickness** (and, optionally, a mould temperature) and — for materials whose data sheet states reaction times — the tool predicts:
- Cream time, gel time, tack-free time, and the resulting processing window
- Adiabatic temperature rise at full conversion, and predicted peak core temperature
- Scorch risk, with margin to the material's scorch temperature

Where a material's data sheet gives no measured heat of reaction, the exotherm figures fall back to a literature-typical value for rigid polyurethane, and the result flags this explicitly as an estimate rather than presenting it as a measurement.

Not available for custom materials (there's no data sheet to calibrate against), and doesn't apply if you don't supply a part thickness.

## Materials Database

### ✅ 4 Catalogued Polyurethane Systems

| Material | Type | Notes |
|---|---|---|
| Genfoam HD12 | High-density pour/mould | Water-blown, ~195–215 kg/m³ |
| Genfoam HD20 | High-density pour/mould | Water-blown, ~290–315 kg/m³ |
| Ecomate Spray EC | Spray foam | Ultra-fast, zero-GWP blowing agent |
| Ecofoam XHD RC | Extra-high-density panel/cavity fill | Rigid, closed-cell |

Materials live in a single CSV (`src/data/polyurethane_foam_database.csv`), which is the source of truth for both the browser UI and the Python engine — adding a material means appending a row, not changing code. See `src/data/database_data_dictionary.md` for the full column reference (viscosity, densities, reaction times, thermal properties, environmental data, etc.).

### ✅ Custom Materials
Enter viscosity, density, flow index, and activation energy directly for a material that isn't catalogued. Values are used as-is for the calculation; environmental impact and cure/exotherm predictions aren't available for custom materials since there's no data sheet behind them.

## Machine Compatibility

### ✅ 2 Machine Classes

| Class | Pressure Range | Typical Application |
|---|---|---|
| Low-Pressure | 8–20 bar | Flexible foam, elastomers |
| High-Pressure | 100–200 bar | Rigid foam, integral skin, dense composites |

The tool reports the pressure to actually set on the machine — whichever governs: what the line demands, or the machine's own minimum operating pressure (a high-pressure machine holds its minimum regardless of what the line asks for, because impingement mixing needs it) — and states which one is governing.

A broader machine-definition framework exists in the Python code (`src/core/machines/machine_definitions.py`, covering ultra-high-pressure, spray, and pouring equipment) but only the two classes above are currently wired into the calculation and the UI.

---

## Environmental Impact

Global warming potential (GWP) of the selected material's blowing agent, and a simple eco-friendliness recommendation. Water-blown and Ecomate-family materials report zero/near-zero GWP; HFC-blown materials would report high GWP where present in the database.

## Learning From Real Outcomes

The physics engine is the only thing making predictions until there's real production data to check it against. Every calculation is saved locally in the browser (no backend — this is a static site); after a part is made, you can record how it actually came out (good / voids / short-shot / scorch / surface defect / other).

Once there are enough **labelled** shots, the app offers to fit a small model on the *residual* — where the physics prediction and the real outcome disagree — rather than trying to predict quality from scratch. Until that point it says so plainly ("No model yet — physics is the only thing answering") rather than showing a synthetic confidence score. scikit-learn is only downloaded once training is actually offered, not on every page load.

Datasets can be exported and imported as JSON, since the app has no server of its own — this is how shots get pooled across machines or people.

## Display Preferences

Pressures can be shown in **bar** (the default, and what the engine, the material data sheets
and the machine specifications all use) or **psi**, since a good deal of injection equipment
is specified in psi and converting by hand at the machine is how mistakes get made.

The preference is applied at the point of display and nowhere else: the calculation, the
stored records and every export remain in bar. Switching units therefore cannot alter a
result or make two saved runs incomparable.

---

## Export

Results can be exported as:
- **JSON** — full result object
- **CSV** — flat parameter/value table
- **Report** — formatted plain-text summary
- **PDF** — a printable report carrying every section the screen shows: the pressure to set and what governs it, warnings, inputs, pressure, flow and the laminar margin, thermal, mix-head temperature, blowing agent, environmental, cure & exotherm, the pressure chart, and sign-off lines

**Units in exports.** JSON, CSV and the text report are data and always quote bar, so a file
means the same thing whenever it is opened. The PDF is the exception: it follows the unit
chosen on screen and states which one on its first page, because it is the copy that gets
printed and carried to the machine.

## Accuracy & Limitations

### What It's Accurate For
- Pressure drop and flow regime (physics-based, standard fluid mechanics correlations)
- Temperature effects on viscosity
- Machine compatibility against the two catalogued pressure classes
- Cure/exotherm timing, where the material's data sheet supplies reaction data

### What It's NOT For
- Detailed mould design
- Full chemical reaction simulation
- Cell structure prediction
- Dimensional tolerances
- Mechanical property prediction (strength, modulus)
- Multi-dimensional thermal field maps (this models the feed line as 1D)

## What's Not (Yet) Wired In

These Python modules exist, are tested, and are loaded into the browser runtime, but nothing in the UI or the main calculation path calls them yet:

- **`src/core/rheology`** — Herschel-Bulkley, Cross, and Carreau non-Newtonian fluid models (only the power-law model is used in the live calculation)
- **`src/core/optimizers`** — standalone pressure and inverse-parameter optimizers
- **`src/core/thermodynamics`** — advanced heat-transfer (convection/radiation/insulation modelling beyond the current shear-heating estimate)

They're implementation, not vaporware — but treat them as "available to build on" rather than a feature you'll find in today's app.

---

## What Changed

An earlier version of this project included a synthetic-data neural-network surrogate and ML quality/defect classifiers trained on generated (not real) data. That code was deliberately removed — see commit `56a4ed3`, "Remove the machine learning that never learned anything" — in favor of the shot-record/residual-learning workflow described above, which refuses to speak until it has real, labelled outcomes. If you're looking at a document (or an old release) that describes "Quality Confidence: 92%" or a neural-network prediction mode, that reflects the removed version, not the current one.
