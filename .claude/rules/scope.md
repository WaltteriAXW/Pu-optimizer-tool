# Scope: sale-readiness, not feature growth

The goal is a clean handover to a buyer. Default answer to a new feature is "not now".

Do, in priority order:
1. Fix bugs that give wrong numbers or break the flow.
2. Make claims verifiable: tests, validation notes, honest limits.
3. Make the repo hand-over ready: licence and ownership clarity, docs, reproducible build, no dead code or stale docs.
4. Make it demonstrable: example runs, user guide, screenshots.

Do not, without the owner's explicit approval:
- Add features, materials, machine types, or new modules.
- Refactor working code for style.
- Add dependencies or a backend.

When a request falls outside the list, say so in one line and ask whether to proceed.
